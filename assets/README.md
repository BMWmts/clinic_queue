# Assets — ภาพประกอบระบบจองคิวคลินิก

ภาพหน้าจอทั้งหมด **แคปจากระบบจริงที่เชื่อมต่อฐานข้อมูล PostgreSQL** ไม่ใช่ภาพจำลองหรือ mockup
ทุกภาพมีแถบคำอธิบายด้านบนระบุหมายเลขภาพ ชื่อหน้าจอ บทบาทผู้ใช้ และคำอธิบายการทำงาน
บางภาพมีกรอบสีแดงพร้อมหมายเลขชี้จุดสำคัญ

- ความละเอียด: 1440 × 900 พิกเซล
- รูปแบบไฟล์: PNG
- วันที่ในภาพ: 17 สิงหาคม 2569 (วันที่มีข้อมูลคิวตัวอย่างในระบบ)
- จำนวน: 19 ภาพ (ขนาดรวม 2.1 MB)

## ตารางเปรียบเทียบสิทธิ์ที่เห็นได้จากภาพ

ใช้ประกอบการอธิบายเรื่องการควบคุมสิทธิ์ในเล่มวิทยานิพนธ์

| ความสามารถ | Super Admin | Admin | Staff | Doctor | ภาพอ้างอิง |
|---|:---:|:---:|:---:|:---:|---|
| เลือก/สลับสาขา | ✅ | ❌ (ล็อกสาขาตน) | ❌ | ❌ | 02, 03, 06 |
| จัดการสาขา | ✅ | ดูอย่างเดียว | ❌ | ❌ | 04 |
| จัดการแพทย์และตารางออกตรวจ | ✅ | ✅ | ❌ | ❌ | 07, 08, 09 |
| ดูรายงาน | ✅ (ทุกสาขา) | ✅ (สาขาตน) | ❌ | ❌ | 05, 10 |
| จัดการคิว / รับ walk-in | ✅ | ✅ | ✅ | ❌ | 11, 12 |
| จองคิวล่วงหน้า | ✅ | ✅ | ✅ | ❌ | 14 |
| จัดการข้อมูลคนไข้ | ✅ | ✅ | ✅ | ❌ | 15, 16 |
| ดูคิวของตนเอง | — | — | — | ✅ | 17, 18 |

> เมนูที่ผู้ใช้ไม่มีสิทธิ์จะไม่แสดงบนหน้าจอ (เปรียบเทียบแถบเมนูซ้ายในภาพ 06 กับ 17)
> แต่การตรวจสิทธิ์จริงอยู่ที่ backend เสมอ การซ่อนเมนูเป็นเพียงการช่วยผู้ใช้ ไม่ใช่กลไกความปลอดภัย

## การสร้างภาพใหม่

สคริปต์ [`capture-screenshots.mjs`](capture-screenshots.mjs) แคปภาพทั้งหมดโดยอัตโนมัติ
(เข้าสู่ระบบทีละบทบาท → เปิดแต่ละหน้า → ใส่คำอธิบายลงในหน้าเว็บ → บันทึกภาพ)
ใช้เมื่อ UI เปลี่ยนแล้วต้องการภาพชุดใหม่ทั้งหมดที่สอดคล้องกัน

**ข้อกำหนดก่อนรัน**

1. backend ทำงานที่ `http://127.0.0.1:8000` และ frontend ที่ `http://localhost:3000`
2. มีข้อมูลตัวอย่างในฐานข้อมูล (`python manage.py seed_dev_data`)
3. ติดตั้ง Playwright (ติดตั้งนอกโปรเจกต์ได้ เพราะเป็นเครื่องมือทำเอกสาร ไม่ใช่ dependency ของระบบ)

```bash
npm install playwright && npx playwright install chromium
```

```bash
node assets/capture-screenshots.mjs
```

**หมายเหตุ:** ค่าคงที่ `DEMO_DATE` ในสคริปต์กำหนดวันที่ที่ใช้แสดงข้อมูลคิว
ถ้ารัน `seed_dev_data` ใหม่ในภายหลัง ให้แก้ค่านี้ให้ตรงกับวันที่ของคิวตัวอย่างชุดใหม่

## การนำไปใช้ในเล่มวิทยานิพนธ์

- **บทที่ 4 ผลการดำเนินงาน** — ใช้ภาพ 01–18 ประกอบการอธิบายผลลัพธ์แต่ละฟังก์ชัน
- **บทที่ 3 การออกแบบ** — ใช้ภาพ 19 ประกอบหัวข้อการออกแบบ API
- **ภาคผนวก คู่มือการใช้งาน** — ใช้ภาพเรียงตามลำดับการทำงานจริง (เข้าสู่ระบบ → ดูคิว → รับ walk-in → จองล่วงหน้า)
- ตารางเปรียบเทียบสิทธิ์ด้านบนใช้ประกอบหัวข้อการออกแบบความปลอดภัยได้โดยตรง
